۱. مقدمه و نحوه استفاده از این سند
این سند با یک هدف مشخص تهیه شده است: ارائه به طراح/توسعه‌دهنده، به‌عنوان جایگزینی برای توضیحات شفاهی، تا وب‌سایت Alanfelez دقیقاً مطابق با طراحی نهایی زیر پیاده‌سازی شود:
https://ratio-donkey-94517275.figma.site
توصیه می‌شود طراح/توسعه‌دهنده علاوه بر مطالعه این سند، صفحات را مستقیماً از لینک بالا نیز مشاهده کند. تصاویر موجود در این سند به‌عنوان یک مرجع سریع و مکتوب عمل می‌کنند؛ اما نسخه آنلاین طراحی، مرجع نهایی برای تعیین دقیق فاصله‌ها، انیمیشن‌ها و نحوه تعامل کاربران با عناصر سایت است.

۱.۱ اصل اساسی: دقیقاً همین را پیاده‌سازی کنید
	•	چیدمان، ترتیب بخش‌ها و متن دقیق فارسی (شامل تیترها، متن دکمه‌ها، برچسب‌ها و تگ‌ها) باید دقیقاً مطابق چیزی باشد که در تصاویر و لینک زنده بالا نمایش داده شده است؛ نه بازنویسی شود و نه به یک ایده مشابه تبدیل شود. 
	•	رنگ‌های مشخص‌شده در بخش ۶ (طراحی بصری)، کدهای HEX دقیقاً استخراج‌شده از طراحی هستند و باید بدون هیچ تغییری استفاده شوند. 
	•	هر جا در طراحی، قابلیتی به‌واسطه سطح اشتراک کاربر قفل شده است (آیکون 🔒)، باید دقیقاً همان رفتار در سایت پیاده‌سازی شود؛ یعنی نه قفل آن حذف شود و نه قابلیت به‌صورت کامل برای همه کاربران فعال شود. 
	•	هر موردی که در طراحی Figma به‌طور کامل مشخص نشده است (برای مثال متن دقیق پاسخ سؤالات متداول (FAQ) یا نسخه موبایل سایت) در بخش ۸ فهرست شده و باید پیش از شروع توسعه، با کارفرما تأیید شود؛ نباید چیزی بر اساس حدس یا سلیقه توسعه‌دهنده تعیین شود. 
۱.۲ ساختار سند
	•	بخش ۲: خلاصه پروژه و اهداف 
	•	بخش ۳: نقشه سایت (Sitemap) و عناصر مشترک در تمام صفحات (هدر، فوتر، نوار نمایش قیمت‌ها) 
	•	بخش ۴: بررسی بصری هر یک از ۷ صفحه — شامل اسکرین‌شات واقعی و توضیحات کامل تمام اجزای صفحه 
	•	بخش ۵: سیستم اشتراک ۴ سطحی، همراه با اسکرین‌شات‌ها و جدول مقایسه کامل 
	•	بخش ۶: راهنمای دقیق طراحی بصری (رنگ‌های واقعی HEX، تایپوگرافی و آیکون‌ها 
	•	بخش ۷: الزامات فنی Backend 
	•	بخش ۸: فرضیات و سؤالات باز که نیاز به تأیید کارفرما دارند 
	•	بخش ۹: مراحل بعدی

6.2 Typography & Layout
•  A readable, modern Persian font with multiple weights (Regular for body text, Bold/Extrabold for headlines and prices) — the exact font name should be extracted from the Figma file
•  Price figures are always shown in a heavy (bold) weight and a larger size than surrounding text
•  The Card is the primary recurring visual unit: rounded corners, very subtle shadow
•  Simple flat icons (not outline/line icons) are used for the services and features sections
6.3 Recurring Interactive Patterns
•  The 🔒 lock icon on content/buttons restricted to a higher subscription tier — this should be built as a single reusable component parameterized by “required tier”
•  Colored access-tier badges (“Free” gray, “Silver” blue-gray, “Gold” gold, “Pro” purple) that repeat consistently next to feature titles
•  A live indicator (blinking green dot) next to the “Live market” label in the price ticker and on the Home page
•  Green/red percentage-change badges with a direction arrow — this element recurs across 6 of the 7 pages and should be a single shared component

7. Technical & Integration Requirements
This section lists backend requirements that aren't visible in the design screenshots but are essential for the site to actually function. The detailed technical architecture (framework, hosting, database) is left to the development team.
7.1 Live Price Data
•  Integration with at least the 3 data sources shown in the design: Iran Mercantile Exchange, Iran Iron Market, Free Market (plus LME for global prices)
•  An automated, scheduled mechanism for updating prices
•  Storage of historical price data to support the range-based charts (1D through MAX)
•  Transparent display of the “source” for each price, exactly matching the “Source” column on the Metal Prices page
7.2 Authentication & User Management
•  Sign-up / login (the exact method must be confirmed with the client — Section 8)
•  A user profile that reflects the current subscription tier
•  A “Verified ✓” badge for identity-verified listers (as seen on listing cards in the Marketplace page)
7.3 Subscription & Payment System
•  An Iranian online payment gateway for monthly/quarterly/yearly transactions
